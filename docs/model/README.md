## Class mapping and preprocessing

`src/data/materials.json` and `classes.json` contain the same 203 identifiers in lexicographically sorted order. Treat this order as part of the model contract; changing it without changing the output mapping silently relabels predictions. The original dataset directory is not required for browser inference.

The worker decodes to RGB, performs Pillow-compatible antialiased bilinear Resize(256), CenterCrop(224), and ImageNet normalization with mean `(0.485, 0.456, 0.406)` and standard deviation `(0.229, 0.224, 0.225)`. Input is `[1, 3, 224, 224]` named `image`; output is `logits`. Softmax produces ranked class scores.

## Retained conversion validation

[`export-validation.json`](export-validation.json) was generated by the project's export script and is retained from the local research artifacts. It compares the original PyTorch and exported ONNX model on 203 reference images:

- Top-1 prediction agreement: 203 / 203.
- Ordered Top-3 agreement: 203 / 203.
- Maximum probability difference: 0.000010192394256591797.

This is an export-equivalence check on reference samples. It does not provide held-out accuracy, calibration, robustness, material composition identification or generalization evidence. The repository does not include model training code or an independent test split. The report was preserved during repository cleanup, not regenerated as a new accuracy experiment.

## Re-export from original weights

The original checkpoint and dataset are separately provisioned local research inputs. With those available at the project root:

```bash
python -m pip install -r requirements-export.txt
python scripts/export_browser_model.py
```

The script writes ONNX, class mapping and validation output to `output/browser-model/`. Review agreement before copying a new model into `public/models/`. If the byte count or model changes, update the expected byte count and cache version in `src/services/browser.worker.ts`, this document's checksum, and the retained report. The exporter checks one reference image per class and assumes each class has an image.

## Reference imagery and provenance

`scripts/prepare_materials.py` creates reference images from the local dataset; `scripts/optimize_images.py` creates thumbnails. The ordered manifest records each image's original dataset-relative path. The `.webp.json` sidecars preserve provenance metadata.

The homepage `leather-study*.webp` image is an AI-generated illustrative material study. It is labeled as illustrative in the UI and is not classifier evidence. The archive images and result comparison specimens are resized dataset images. Project screenshots in `docs/images/` were retained from prior verification artifacts.

The optional `scripts/embed-provenance.cjs` helper requires an Impeccable CLI installation, resolved from `IMPECCABLE_EXECUTABLE` or `PATH`. It is not part of installation or build.
